# 当前架构

主界面、透明桌面小窗口和数据服务均运行在同一个 Go 进程中。MyGO 0.5.2 绘制主页面、托盘和标准窗口；小窗口由 Go 调用 Win32 创建逐像素透明窗口，并使用 MyGO 的内存绘制引擎渲染字体、SVG、图表和玻璃表面。应用没有 WebView、Electron、React、Vite、Node 子进程或小窗口 TCP 通信。

## 源码入口

| 路径 | 职责 |
| --- | --- |
| `main.go`、`mygo.json` | 原生启动、图标与语言资源嵌入 |
| `internal/nativeapp/theme.go`、`shell.go` | 系统色板、字体、弹簧动画与通用控件（含模型标志）；侧栏、玻璃工具栏、筛选与命令面板 |
| `internal/nativeapp/overview.go`、`activity.go`、`history.go`、`calls.go`、`quota.go`、`settings.go` | 五个页面及其卡片、表格和详情 |
| `internal/nativeapp/` 其他文件 | 窗口控制、图表栅格化、托盘与导出 |
| `internal/nativeapp/widget*.go` | 小窗口状态、布局、绘制、动画、透明 Win32 窗口和验收 |
| `internal/monitor/` | modernc SQLite、日志解析、增量采集、账号、价格、统计与额度 |
| `assets/locales/`、`internal/nativeapp/icons/` | 语言字典和嵌入的 SVG 图标 |
| `internal/testfixture/`、`cmd/fixture/` | 隔离验收的合成统计数据 |
| `cmd/repair/` | 从源码恢复损坏数据库到新文件，不覆盖原库 |
| `scripts/` | 无 npm 依赖的构建、NSIS 打包和安装验收 |

## 数据与进程

`monitor.Service` 独占 `monitor.sqlite`，用 `monitor-owner.json` 防止双进程写入。所有数据库操作经过串行队列，扫描事务与设置、价格、清空历史操作不会交叉。增量扫描每 3 秒进行，完整目录发现每 60 秒进行；额度查询另行发起后回到服务队列写入。

MyGO 页面直接调用 Go 服务获取按页面裁剪的独立 Go 快照；结果与事件在同一进程中传递，不再经过 JSON 往返。请求参数仍先序列化，隔离调用方的可变数据；`--stdio` / `--snapshot` 保留原 JSON 协议。小窗口调用同一服务的 `widget` / `refresh` 方法：可见时每 3 秒刷新，更新事件触发立即刷新；同一时间仅有一个请求，期间收到的更新合并为下一次读取。后台请求通过主窗口的 GUI 调度器回到主线程，不从工作线程修改小窗口状态。隐藏后停止轮询，退出时取消请求并释放窗口、定时器与 GDI 位图。

当前数据库位于 `%APPDATA%\codex-monitor`。小窗口位置、置顶和显示模式仍保存在 `widget-window.json`，兼容旧版设置；主窗口状态保存在 `native-shell/`。已有 SQLite 数据库先通过只读连接执行完整性检查，避免失败退出时将 WAL 回写到主库；发现损坏后拒绝写入并显示具体启动错误。

完整性检查失败的提示提供“备份并修复”。`monitor.RepairProfile` 独占数据目录，在私有副本中读取数据库和已提交 WAL，绕过索引逐行重建表，再重建索引并执行完整的 `integrity_check`。只有全部读取和验证成功才将原库及 WAL / SHM 移入 `database-backups` 并安装新库；替换失败时尝试回滚。设置、价格、账号、扫描偏移和清空历史边界一起保留，无法读取的行不会被静默丢弃。修复成功后自动重启；随安装包提供的 `--repair-database` 使用相同流程。

## 统计约束

- Codex 采集桌面与 CLI 来源（包括交互终端、codex exec、MonoCode）；保留原始 originator，sessions.source 记录 desktop / cli / pi / unknown。MonoCode 以 monocode / monocode-text 标识调用 app-server，日志 source=vscode 仍按 CLI 后端归类。新格式按响应 ID 去重；旧累计记录取差分，CLI 的差分 ID 包含会话，累计回退时处理重置。复制历史中早于会话创建时间的用量只更新累计基线。
- 数据库通过 PRAGMA user_version 管理迁移，历史无版本结构为 0，账号字段与索引为 1，来源与 files.parser_version 为 2。迁移在同一事务提交，拒绝更高版本；修复重建保留版本。
- 结构版本 4 的会话来源新增 `vscode`，解析版本 3 识别 `codex_vscode` 并重扫已有日志。已知 Desktop / CLI 身份优先于 `source=vscode`；IDE 旧累计差分按会话隔离，新响应沿用全局响应 ID 去重。
- 解析版本 4 在同会话恢复元数据后保留模型、轮次与累计状态，并读取明确的模型变更事件；重扫只补回缺失模型，不覆盖已有 Token。模型缺失的记录也可按唯一 Token / 时间签名关联已采集首字事件，并从该事件补回模型；已知模型冲突或候选歧义时不进行该关联。
- 结构版本 3 新增 `request_events`：与 `usage` 分开存储 TTFT、失败、重试和安全的关联字段。OTel 不重复写入用量；任务 / 全局费用仍来自 `usage`。TTFT 优先响应 ID，其次同会话模型、2 秒内 Token 签名唯一匹配，歧义保持未关联。Pi 请求关联键将 provider 诊断归入其最终 assistant 响应轮次。
- 扫描文件按解析版本决定重读，首次升级补采旧 CLI 文件，即使文件大小、修改时间不变也重读。重读保留响应去重、账号归属与 clearedAt 边界，文件失败回滚统计与偏移并在后续扫描重试。
- pi 仅处理可识别的官方 Codex 登录来源，缓存读取 / 写入属于输入，推理 Token 已包含在输出中。
- 账号通过观测区间归属；未知身份保持未归属。价格按生效时间选择，手动版本优先。
- 主窗口服从用户筛选；小窗口用量汇总全部本机账号，额度仅取当前 Codex 账号。
- 费用、缓存和额度缺失时保持未知。过期额度显示未知，旧快照通过提示标记。
- 逐次列表区分用量记录、失败事件和重试事件；TTFT 缺失不补算，失败 / 重试没有独立用量时不计费用。首字分位数使用实际 TTFT 样本；任务费用占比仅以已定价用量为分母。
- 清空历史设置边界，防止旧日志重放。趋势图使用单调三次插值；额度图以线性时间精简密集采样的绘制点，在重置和采样空档处断开。提示和键盘选择保留全部原始记录，详见 [曲线平滑](chart-smoothing.md)。

图表缓存当前指标的原始采样和分段，悬停按时间二分查找。独立的 `x/image/vector` 栅格化任务在后台生成一张不可变曲线图层，完成后通过通道交给 GUI；不跨线程操作 MyGO 的共享纹理图集。图层包含曲线、填充和重置提示，网格、悬停指示和文本由 GUI 绘制；动画改变裁剪与位置。准备期间仍显示当前记录的矢量曲线，过期任务结果丢弃。主题、DPI、绘图区和数据改变时重建，数据未变的快照继续复用；切换指标或离开页面释放旧图层。见 [长历史图表性能](chart-performance.md)。

## 逐次请求分析

本机请求采集由同一 `monitor.Service` 管理。开关开启且非离线时监听 `127.0.0.1:<端口>/v1/logs`，只接受有限大小的 OTLP HTTP JSON（支持 gzip）；HTTP 工作线程将白名单事件放入现有串行队列。关闭、端口切换和退出释放监听器，端口失败会回滚设置。`Scan` 额外只读检查 Codex `logs_*.sqlite`，在 Monitor 内保存诊断游标并检测数据库重建，不写诊断源。

主窗口通过 history 快照读取 `calls` 和 `callDetails`：调用列表每页 50 条，展开任务每页 25 条，记录状态与排序由服务处理。仅请求逐次视图时返回全局调用列表，任务明细按需读取；列表使用稳定记录键、虚拟滚动和键盘展开。内置 Pi 扩展嵌入可执行文件，开启采集时自动安装到 Pi 的 extensions 目录，并合并当前 Codex home 的 OTel 配置。`telemetry_setup.go` 以 TOML AST 范围保留其他配置字节，修改前备份；Monitor 仅记住管理的两个非敏感字段和扩展哈希。关闭时恢复仍属于程序的字段及移除未被修改的扩展；离线模式不写客户端文件，配置冲突分别显示。新安装默认开启，升级保留开关，启动端口冲突自动寻找空闲端口并同步客户端。采集步骤与限制见 [逐次用量与首字分析](request-analysis.md)。

## 小窗口与动画

原生小窗口保持 560×380 DIP；卡片为 536×356，圆球为 120×120，位于窗口右上角。命中、提示与键盘焦点区域、TPS 采样和中英文文案以旧版为基线。2.9.1 起小窗口与主窗口共用 `theme.go` 的色板与字体：材质表面上放置与主窗口一致的圆角卡片，指标使用相同的彩色徽章、Display 数字、胶囊进度条和渐变面积图，状态为着色胶囊；跟随应用的浅色 / 深色外观（系统切换、设置中更改主题时重绘），关闭透明效果时改用不透明背景。圆球切换改变绘制轮廓，不改变原生窗口尺寸。

Win32 `UpdateLayeredWindow` 接收 Go 渲染的预乘 BGRA 位图。透明区域通过 `WS_EX_TRANSPARENT` 传递鼠标输入，定时器在鼠标进入表面时恢复输入。拖动使用物理屏幕坐标和 5 DIP 阈值，避免移动窗口后客户区坐标不变造成误判；固定尺寸随每次移动重申，避免 DPI 舍入累积。处理 DPI 与显示器变化，并在展开前将卡片移回工作区。

保留 680ms 的卡片 / 圆球轮廓动画、内容缩放及模糊、进出淡入淡出、750ms 进度条、悬浮高光和 700px 透视倾斜。支持鼠标拖动、单击圆球展开、三点收起、双击标题 / 点击标志返回主窗口、右键菜单、置顶、手动刷新、键盘 Tab / Enter / Space 和设置恢复。遵循系统减少动态效果和透明度偏好。

主窗口与小窗口现在同时过渡，透明度交给 Windows 合成，不重建整页透明度场景；进出动作采用淡入淡出，去掉进出时的微小缩放和位移。小窗口复用稳定场景与模糊工作区，非微小模糊在半分辨率处理，相同整数滤波核复用结果。指标图层比较当前进度、悬浮幅度与光照位置，变化时才重绘，并绘制动画最终值。切换期间暂存新数据，动画结束后提交，避免内容绘制占用合成帧间隙。

活动动画由 15ms Go 定时器投递私有 Win32 帧消息，原子标记保证最多排队一帧；收到消息后在 GUI 线程绘制与合成。停止动画时取消该定时器并降低到 100ms 的鼠标穿透检测 / 轮询时钟，隐藏或销毁时全部停止。窗口转换可从当前透明度反向继续，不使用固定等待后再显示目标窗口的串行流程。

模型筛选列表使用 `usage(model,account)` 索引做松散索引扫描，每个模型只需一次索引查找；覆盖范围的最早 / 最晚时间分别走时间索引。排行、合计和活动日历在逐行累加时使用普通字段而不是 map，按时间排序的记录在同一 UTC 分钟内复用时间桶，不再逐行解析时间。统计按模型建立保持价格优先级的降序索引，用二分查找选择生效版本。总览、日历、小窗口和任务汇总逐行读取 SQLite，复用行容器与值类型费用结果；总览范围覆盖日历时，共用读取与计费。逐次分页以有界堆保留当前页之前的候选，TTFT 样本仍完整统计；用量与诊断的时间序列线性合并。SQLite 扫描数组、JSONL 读取缓冲区与扫描期的清空边界复用；超出 1 MiB 的长行工作区在文件结束后释放。原生快照沿用同构 Go 切片，历史列表仅在快照、筛选或排序变化时重新派生。隐藏主窗口暂停统计快照，恢复后再刷新。

## 主界面设计

工具栏与内容共用 1320 DIP 最大宽度和 28 DIP 内边距，操作按钮置于原生窗口控制按钮下方，与末尾筛选框右对齐；筛选换行时也靠右排列。时间范围切换保留趋势图元素身份与键盘焦点，更新数据及后台图层后重播原有 780ms 展开动画；裁剪沿实际曲线覆盖的时间段推进，稀疏采样不会因横轴留白而瞬间完成。未更换筛选的后台刷新不重播动画。

Store 最多缓存 8 份页面快照与 8 份年度活动汇总，不缓存逐条原始用量。日期、时区、筛选和页面进入缓存键，活动汇总不含时间范围，切换短范围时可复用整年结果。每次快照检查同一 SQLite 连接的 `total_changes()` 与外部提交的 `data_version`，任意写入后保守清空缓存；返回值递归复制，GUI 无法修改缓存。活跃任务在命中缓存时仍按最近 2 分钟重新计算，跨午夜自动更换缓存键。测量口径见 [范围切换性能](range-performance.md)。

2.9 版本按 macOS / iPadOS 的设计语言重做主窗口：隐藏系统标题栏，侧栏使用 Mica 材质（`VibrancySidebar`），内容区顶部为随滚动淡入的玻璃工具栏（`glass.ScrollEdge`）。浅色 / 深色两套系统色板集中在 `theme.go`，字体为 Segoe UI Variable，数字使用等宽数字特性。所有页面由同一组控件组成：圆角卡片、标题行、彩色图标徽章、分段控件、弹出菜单、分组设置行和空状态。

动画统一使用三种弹簧（`springSnappy`、`springSmooth`、`springGentle`）：卡片按顺序错开 40ms 入场，侧栏选中胶囊在项目间滑动，指标卡片悬停时轻微抬起，额度圆环从零开始转到当前值，数字使用数值内容过渡。图表以渐变填充、细线网格和悬停气泡显示数值，入场时自左向右展开。命令面板（Ctrl+K）用玻璃面板列出页面与常用操作。系统“减少动态效果”开启时，所有动画直接到达终点。

## 活动页面交互

热力图按快照版本、年份和指标缓存在 `heatmap` 结构中：日期与格子之间的换算和指针命中都是 O(1) 计算，整张网格只用一个绘制元素。网格入场时按距离产生波纹显现；悬停或方向键选择会高亮格子并在下方显示当天详情，Enter 打开当天记录。小时图在单个绘制元素中渲染 24 个渐变柱条，与鼠标定位共享等宽小时划分。

## 软件更新

设置使用 `plugins/updater/native`，由 MyGO 提供原生版本说明、检查结果、下载进度及安装 / 重启窗口。默认不开启自动检查；可在设置中开启每日自动检查和后台自动下载，SDK 保存选择、验证签名并在下次启动时应用下载的更新。离线模式禁止修改自动更新选项。`mygo.json` 指定 GitHub 仓库与 Ed25519 公钥，构建脚本将生产标记、版本、平台更新地址和公钥链接到 SDK；直接 `go run .` 没有更新发布配置，SDK 提示更新未启用。

保持已有 NSIS 安装流程，`scripts/updates.cjs` 额外归档两份运行文件，按 MyGO 格式对归档的 SHA-256 摘要进行 Ed25519 签名，并生成平台清单。发布同时上传归档和清单后，应用才从最新 Release 检查和验证更新。密钥读取环境变量或仓库外的本机密钥文件，公钥匹配失败时打包终止；升级保留独立数据目录。`OnQuit` 在 SDK 重启新进程前关闭数据服务并释放数据目录锁，避免重启进程撞上尚未关闭的旧服务。

## 构建与验收

品牌图标以 160 px 嵌入（最大 40 DIP 的 4 倍），一次解码。小窗口收缩后释放卡片图层，形态动画结束后释放模糊区，隐藏两秒后释放离屏绘制器和本机 DIB；模型与位置状态保留，快速切换取消延迟释放。GUI 的默认 GC 为 50%，Go 软预算按窗口像素数提供至少 80 MiB，显式环境设置优先，CLI 不设置此策略。回收空闲图像页在 GUI 线程外执行。真实 Windows 私有字节 / 私有工作集测量与冷恢复成本见 [GUI 内存报告](gui-memory.md)。

`go run .` 可从源码运行，`go test ./...` 执行测试。npm 脚本只使用 Node 标准库，不需要安装 npm 依赖。`npm run build` 以 `mygo_noinspector` 标签生成 `build/native/Codex Monitor Native.exe` 并复制 `icon.ico`，构建目录只有这两个文件；所有绘制资源已嵌入可执行文件。

`npm run package` 使用 NSIS / LZMA 打包完整应用，生成安装包和 SHA-256 校验文件。安装按当前用户进行，并创建快捷方式与 Windows 卸载记录；必须从托盘退出运行中的应用后才能更新。升级会按已知清单清理旧主程序和旧小窗口的 Electron 文件，保留用户额外添加的文件和全部数据。清单位于 `scripts/legacy-app-files.nsh`、`scripts/legacy-widget-files.nsh`，只是升级清理规则，不包含旧实现。

`npm run package:check` 使用独立的安装目录、快捷方式和注册表项，验证逐文件哈希、已安装服务和数据库修复、旧运行时清理、运行保护、重复安装及卸载，不覆盖本机应用。

`npm test` 验证数据服务、数据库修复、主界面及小窗口模型 / 绘制。`npm run native:check` 实际启动隔离的原生应用，验收五页、全历史逐次调用、过渡帧、窗口控制和 Win32 小窗口：逐像素透明、DPI 固定尺寸、拖动、圆球命中、键盘展开、中英文、额度过期、错误重试、置顶和状态保存。注入过期 / 断连场景前，验收等待真实请求结束并临时暂停自动轮询，随后显式刷新恢复；正常运行的轮询不变。`npm run widget:check`、`npm run test:ui` 指向这套原生验收。报告和截图保存在被 Git 忽略的 `artifacts/`，所有数据均为合成演示数据。
