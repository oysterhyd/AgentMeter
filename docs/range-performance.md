# 时间范围切换性能

2026-10-17，Windows x64，AMD Ryzen 7 8845H，Go 1.27.1。使用 `reviewStore` 的 20,000 条已定价调用、100 个已完成任务和逐次首字事件，全部为临时目录中的合成数据。

## 改动与边界

- 趋势图元素不再把整个筛选 JSON 作为身份。范围变化保留焦点、元素及后台图层，重新播放原有的 780ms 展开动画；首次进入页面和切换指标同样保留动画。动画沿实际采样覆盖的曲线展开，避免“今日”只有开头几小时数据时被空白横轴挤成瞬间完成。系统减少动态效果设置仍直接显示终态。
- 最多保留 8 份独立页面快照、8 份年度活动汇总，不保留原始用量行。年度汇总在范围切换间共享，页面结果按完整筛选隔离；返回值递归复制，调用方不能修改缓存。
- 通过 SQLite `total_changes()` 和 `data_version` 检查本连接与外部提交。任何写入都保守失效，包括价格、账号、设置、扫描和清空历史。跨午夜与时区变化更换缓存键；活跃任务即使命中缓存也按当前时间重新计算。
- 统计查询只取计算需要的列，减少数据库解码和映射分配，不裁剪统计记录、图表原始采样、筛选、分页或导出。

## 测量

改动前运行现有 `BenchmarkReview`，每项 3 次；改动后运行 `BenchmarkRangeSwitch`，每项 10 次。以下是本轮单次运行的平均值，冷查询容易受机器负载影响，不作为严格回归阈值。

| 场景 | 改动前，无缓存 | 改动后，冷查询 | 改动后，缓存命中 |
| --- | ---: | ---: | ---: |
| 总览 / 全部 | 55.36ms | 48.89ms | 0.079ms |
| 任务历史 / 全部 | 94.51ms | 75.42ms | 0.130ms |
| 逐次调用 / 全部 | 259.09ms | 217.29ms | 0.239ms |

“今日”首次读取为 58.51ms，年度活动汇总已存在时为 36.53ms，完整页面命中为 0.062ms。该样本的用量集中在最近数小时，“今日”仍包含大部分记录。

总览冷查询的分配从 4,356,197 B / 327,253 次降至 3,095,500 B / 207,522 次；命中时为 21,376 B / 214 次。完整命中时不重新遍历历史记录，但仍复制派生结果并查询活跃任务。

这些数值是服务快照的时间，不包含 780ms 趋势展开动画，也不代表整帧显示延迟。首次查询、数据写入后的下一次查询和缓存淘汰后仍需要完整聚合。自动扫描写入状态也会失效缓存；没有通过延迟新数据、跳过扫描或禁用动画来维持性能。

```powershell
$taskGo = node -p "require('./scripts/go.cjs')"
& $taskGo test ./internal/monitor -run '^$' -bench '^BenchmarkRangeSwitch$' -benchtime=10x -benchmem
npm run native:check
```

基准原始输出在 `artifacts/range-benchmark.txt`。原生验收增加全部预设范围、自定义日期和连续快速切换；`artifacts/native-acceptance/ranges-result.json` 记录 GUI 调度和快照提交时间，`ranges-enter.png` 与 `ranges.png` 是真实窗口的动画中途及完成截图。像素回归验证浅色、深色、稀疏采样、连续切换、图层与键盘焦点复用、后台刷新不重播及减少动态效果。完整验收同时覆盖五页、高 DPI、窗口操作、桌面小窗口及 VS Code 来源 CSV。

本轮原生合成数据验收的 9 次范围切换，包含 GUI 调度的快照提交耗时为 20.04–46.36ms；该窗口数据集比上述 20,000 条调用基准小，不混为同一个工作负载。分段控件与数字内容过渡仍沿用现有动画。
