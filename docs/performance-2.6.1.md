# 2.6.1 性能与代码简化报告

## 审查范围与改动

审查覆盖 Go 数据服务、SQLite 查询、Codex / pi 日志采集、价格与用量统计、历史列表、主界面动画、小窗口绘制与调度、构建及安装更新流程。改动保持账号归属、价格生效与手动优先级、未知值、清空边界、完整性检查和数据修复规则。

| 路径 | 改动与复杂度 |
| --- | --- |
| `monitor/metrics.go`、`activity.go` | 一次 O(P) 建立按模型的价格索引，将 N 条用量的 O(NP) 价格遍历改为 O(P + N log Pm)，Pm 是该模型的版本数。保留生效日期、手动版本和 ID 的排序优先级。总览范围覆盖日历时复用已读取的用量行，减少一次 SQLite 查询和 O(N) 行对象分配。 |
| `monitor/store.go` | 常见字符串直接返回；一次查询复用列扫描数组，取消每行两个临时数组。结果行仍独立持有数据。 |
| `monitor/scan.go` | 普通 JSONL 行借用 `bufio.Reader` 缓冲区；超长行使用可复用缓冲区，保留原有不提交未完整行的行为。普通行额外空间从每行 O(L) 分配改为固定读取缓冲区。 |
| `monitor/activity.go` | 合并主窗口与小窗口的最新额度查询；额度桶选择从排序加嵌套遍历改为一次 O(Q) 遍历。 |
| `nativeapp/data.go`、`history.go` | 快照进入 UI 时转换同构列表，随后读取 O(1) 借用切片。复用服务端默认排序；筛选与其他排序按快照版本、搜索和排序键缓存，未变化的动画帧不再 O(N log N) 重排。 |
| `nativeapp/motion.go`、`widget.go` | 删除 36 行整页透明度状态机及固定等待的串行切换流程，复用同一动画插值类型；系统合成两个窗口透明度，支持途中反向切换。主窗口隐藏时停止统计快照请求，切换结束再提交重数据。 |
| `widget_render.go`、`widget_effects.go` | 稳定场景、指标图层、模糊工作区与相同滤波核复用。较明显模糊按半分辨率处理，像素工作量约为全分辨率的 1/4；微小模糊保持完整分辨率。最终动画帧仍准确提交。 |
| `widget_windows.go` | 活动帧投递可合并的原生消息，防止 WM_TIMER 被界面消息延后；最多一个帧消息待处理，静止时降低到 100ms 轮询。隐藏 / 销毁时释放定时器、GDI 和调度资源。 |
| 设置与构建 | 使用已有 MyGO 0.2.15 原生 updater，无新增运行时。补齐生产版本、更新源、公钥、签名归档及清单。 |

简化针对重复流程与重复计算，并非压缩源码行数。新增缓存、签名发布支持、回归测试和测量工具后，总源码行数增加；没有删除统计、修复或原生交互功能。

## 测量条件

- Windows amd64，AMD Ryzen 7 8845H / Radeon 780M，Go 1.27.1，MyGO 0.2.15。
- 原始基线：v2.6.0，提交 `64944ed3deb794185810b98f5e2061429560fea9`；优化候选：2.6.1。基线先加入同一组 benchmark，随后修改实现。
- Go benchmark：每项 1 秒，独立运行三次，表格取三次中位数。建库、种子数据和价格索引准备时间不计入热点循环；完整 Snapshot 指标包括每次建立价格索引。
- 数据库场景：100 个会话、20,000 条合成用量，固定虚拟时间及 `range=all`。JSONL 场景：10,000 条 1KiB 行，约 9.77MiB，测量内存读取与筛选，未包含磁盘 / SQLite 写入耗时。
- 小窗口离屏场景：150% DPI，固定虚拟时间；形态测试持续覆盖展开中间帧与模糊，渲染指标不含 Win32 提交。所有数据均为合成数据，未对真实用户数据库进行基准改写。
- 分配字节是每次操作的累积分配，**不是应用常驻内存或峰值 RSS**。三次样本仅作本机回归比较，未声称统计显著性或跨设备等比例收益。

| 基准 | 2.6.0 耗时 | 2.6.1 耗时 | 耗时变化 | 累积分配前 → 后 |
| --- | ---: | ---: | ---: | ---: |
| 20,000 条用量：总览快照 | 191.33ms | 93.18ms | -51.3% | 76.70 → 33.52MiB，-56.3% |
| 历史快照 | 101.50ms | 61.34ms | -39.6% | 37.64 → 24.65MiB，-34.5% |
| 活动日历快照 | 112.41ms | 62.75ms | -44.2% | 37.49 → 24.06MiB，-35.8% |
| 设置快照 | 11.98ms | 11.14ms | -7.0%，差异较小 | 158.68 → 143.32KiB |
| 13 个价格版本：单条价格匹配 | 867ns | 489ns | -43.6% | 416 → 368B |
| 1,000 个价格版本：单条价格匹配 | 43.77µs | 0.513µs | 约 85 倍 | 4,980 → 368B；198 → 6 次分配 |
| 10,000 条 JSONL 读取 / 筛选 | 4.16ms | 1.35ms | -67.5% | 10.08MiB → 268.58KiB；10,006 → 2 次分配 |
| 小窗口形态展开中间帧 | 82.55ms | 23.29ms | -71.8% | 16.99 → 2.89MiB，-83.0%；约 47 → 23 次分配 |

相同场景、相同整数模糊核的结果现在命中缓存；单独强制执行完整分辨率滤波仍约 30.23ms，与原来约 30.01ms 相近，主要收益是工作区复用（热调用分配从约 9.84MiB 降至 0）和减少调用次数。没有将缓存命中耗时冒充重新计算滤波的耗时。

`BenchmarkMainVisibility` 调用 `ui.Tester.Frame`，旧版一次调用可能内部跑到 20 个动画帧，新版稳定场景可立即结束。该整次调用由约 275.36ms 降至 0.825ms，但它不是单帧或实际屏幕 FPS，因此不列入单帧比较表。

## 真实窗口切换

在隔离的真实 Win32 窗口中，分别测量四次返回主窗口、四次进入小窗口，包含透明度合成，另验证 45ms 间隔的连续反向操作。

| 方向 | CPU 中位数 / P95 | 帧消息间隔中位数 / P95 | 最长间隔 |
| --- | ---: | ---: | ---: |
| 返回主窗口 | 1.04 / 2.16ms | 14.94 / 18.44ms | 19.15ms |
| 进入小窗口 | 1.08 / 6.00ms | 15.02 / 21.26ms | 23.00ms |

本次迭代中保留 WM_TIMER 的中间方案出现约 154ms 的首帧消息间隔；改用合并的帧消息后，上述验收中不再出现该停顿。这个 154ms 是**中间方案**的诊断结果，不是另行测出的 v2.6.0 屏幕帧率。原有 180ms 串行等待已经移除，目标窗口会立即开始显示。

帧消息间隔不等于显示器实际呈现间隔。结果表明切换调度接近 60Hz 的预算，但仍有偶发超过 16.7ms 的间隔。复杂形态动画的离屏耗时仍约 23ms，强制完整小窗口悬浮重绘约 31ms，不能保证所有效果全程稳定 60FPS；当前剩余开销主要在 MyGO 软件位图采样、玻璃 / 阴影绘制和未缓存的滤波。

## 验证与复现

```powershell
go test ./...
go vet ./...
go test ./internal/monitor -run '^$' -bench 'Benchmark(Snapshot|CostLookup|ScanLines)' -benchmem -benchtime=1s -count=3
go test ./internal/nativeapp -run '^$' -bench 'Benchmark(Widget|MainVisibility)' -benchmem -benchtime=1s -count=3
npm run native:check
npm run package
npm run package:check
```

测试涵盖价格并列优先级、退役与未知版本、活动日历复用范围与未来日期、普通 / 超长 / 未完整 JSONL 行、JSON 结构保持、列表缓存失效、动画最终帧、设置更新入口、真实双向切换、快速反向切换，以及原有账号、费用、修复、安装与卸载规则。原生验收同时确认签名 updater 已启用。

本机原始输出在 `artifacts/performance/`，窗口测量及截图在 `artifacts/native-acceptance/`；这两处由 Git 忽略。签名发布过程验证密钥匹配和归档签名；Release 发布后通过程序的 `--check-updates` 验证真实更新源。安装验收使用隔离目录与登记项，未覆盖用户的本地安装。
