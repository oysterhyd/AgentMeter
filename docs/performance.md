# 2.8.2 代码审查、简化与性能报告

基线：2.8.1，提交 `f56496193e0fdc37cb0e38fa232911f75d98caa1`。审查覆盖采集、统计、五页界面、小窗口、修复、配置和分发。主要收益是减少中间记录、重复排序和进程内 JSON 往返。**累积分配下降不等于整个应用峰值内存下降。**

原始样本、三次中位数、包体积和代码行数见 [performance-results.json](performance-results.json)。旧收益另存为 [2.6.1 报告](performance-2.6.1.md)，没有重复计入本次比较。

## 功能审查与代码简化

| 功能 / 模块 | 改动或保留理由 |
| --- | --- |
| 总览与排行 | SQLite 逐行聚合，借用一个行容器；费用改用值类型。总览范围覆盖日历时共用读取和计费，无项目筛选时省去会话连接。保持生效日期、手动优先级、退役与未知费用。 |
| 日历、小时分布、连续活动 | 流式累积日期、小时和会话集合，取消整批用量行存储。保留年度、筛选、未来日期边界和活动动画。空间仍随日期和不同会话集合增长。 |
| 任务记录与模型明细 | 所选任务的调用直接进入汇总器，保持全任务口径、模型出现顺序、账号、状态和搜索，省去调用数组及其二次遍历。 |
| 调用排序、分页、占比 | 用量与诊断有序流线性合并；时间排序借用 SQL 顺序或反转，数值排序共用比较器。分页用有界堆；返回页复制切片，避免继续引用整批记录。状态筛选跳过不需要的流。 |
| TTFT、失败与重试 | 保留所有匹配样本和最近秩 P50 / P95；最大调用并列选择保持显示排序，费用占比仅用已定价记录。浮点累加顺序改变可影响最后几个二进制位，回归容差为相对 `1e-12`。 |
| CSV | 两套写入逻辑合并为一个写入器；普通用量从游标直接写入，取消行 / 单元格字符串数组。BOM、CRLF、引号、换行、公式防护和列顺序不变。 |
| Desktop / CLI / MonoCode / Pi 扫描 | 共用读取缓冲区和扫描期的清空边界；未变化文件跳过状态解码，超出 1 MiB 的工作区在文件结束后释放。保留去重、累计差分、重放、解析版本、取消和失败回滚。 |
| 账号与 OAuth | 字符串切分读取 JWT 载荷；scope 直接检查字符串切片，删除 `[]any` 转换。观测区间可能重叠，保留优先级匹配，避免改变归属。 |
| 额度、采样、提醒 | 保留可执行文件缓存、单次查询、账号切换保护、重置 / 空档与提醒去重。网络查询频率和曲线采样算法不变；基准没有稳定速度收益。 |
| 首字接收与自动配置 | 接收器使用 Go 值结果；保留白名单、大小限制、串行写入、配置备份 / 所有权、端口冲突和关闭恢复。Pi 钩子及诊断关联规则不变。 |
| 数据传递、设置、托盘、更新 | UI 直接接收独立 Go 快照和事件，删除结果 JSON 往返。输入仍先序列化隔离可变参数，命令行 JSON 协议保留。语言、主题、价格、提醒、托盘和签名更新不变。 |
| 图表、小窗口 | 分段借用原切片；模糊滑动求和改用步长，减少像素分支并支持不同 stride。保持动画、透明、拖动、置顶、命中、键盘和状态恢复。 |
| 数据库修复 | 每张表复用预编译插入语句；继续完整读取、重建索引、校验、备份与失败回滚。结构版本仍为 3，没有新增迁移。 |
| 构建、安装 | PNG IDAT 无损重压缩；安装使用 16 MiB LZMA 字典，更新归档使用 gzip 9。保留完整运行文件、双语向导、用户数据、升级和卸载，无新增依赖。 |

简化消除了重复流程和容器，**应用 Go 源码没有整体缩短**：`main.go`、`internal/monitor` 和 `internal/nativeapp` 的非测试源码由 **10,020 → 10,355 行，净增 335 行**。新增部分包括汇总器、有界堆、共用比较器和实际调用页验收；基准、回归测试和测量脚本另外统计。

分页候选维护由 `O(N log N)` 排序降为 `O(N log K)`，记录存储由 `O(N)` 降为 `O(K)`，`K=min(N,50×页码)`，末页可能仍为 `K=N`。TTFT 样本仍需 `O(T)` 空间和 `O(T log T)` 排序，SQLite 排序不包含在候选堆复杂度中。有序合并为 `O(U+E)`；图表分段仍为 `O(N)` 时间，额外复制空间降为 `O(分段数)`。

## 测量条件

- Windows amd64，AMD Ryzen 7 8845H，Go 1.27.1，MyGO 0.2.15；默认 GOMAXPROCS=16。
- 同一基准源码在原提交和候选代码上运行；每项 1 秒、三次，取中位数。建库和种子准备不计入热点循环。
- 主场景：100 个会话、100 个完成任务、20,000 条已定价用量与 20,000 条关联首字事件；固定虚拟时间、`range=all`、列表每页 50 条。
- 扫描：1,000 条合成用量，包含文件读取、解析、SQLite 写入。修复包含上述数据库的完整读取、重建与校验。
- UI 传递：167 条用量、155 个任务、8 条失败 / 重试事件。小窗口离屏绘制为 150% DPI；图表压力场景为 20,000 点 / 20 段。
- 真实进程对相同数据库做三轮交错运行，100ms 采样私有字节，读取 Windows 工作集峰值；两版共用隔离验收同步和调用页面辅助代码，生产算法来自各版本。
- 输入全部合成，离线运行，不含在线额度查询的 Codex App Server 子进程。三次本机样本不能证明统计显著性或跨设备的等比例收益。

| 真实窗口场景 | 私有字节采样峰值 MiB：前 → 后 | 工作集峰值 MiB：前 → 后 | 总 CPU 时间：前 → 后 |

**本轮没有测到整个 GUI 流程峰值内存的稳定下降。** 软件绘制、图像缓存、验收截图和 Go GC 时机对峰值影响较大，单次分配减少没有直接转换为更低的流程峰值。汇总的临时对象已减少，剩余 GUI 内存需要在绘制引擎层继续分析。本次未修改全局 GC 参数或删减视觉效果。

安装包约 **7.48 MiB**。两张 PNG 共减少 **65,019 字节**，扫描行和逐像素结果完全一致，元数据保留。完整运行目录仍为主程序与图标两文件。

## 验证与复现

已通过完整 Go 测试、`go vet`、监测与原生界面 race 测试、Pi 扩展测试、真实五页与调用页 / Win32 小窗口验收，以及安装、升级、快捷方式、登记、运行保护、已安装服务、数据库修复和卸载验收。

新增回归覆盖 6 种调用顺序 × 5 种状态 × 4 种搜索 × 5 个页码；JSON / Go 协议与快照独立性；取消后的扫描边界；CSV 精确输出；模糊与不同 stride 的逐像素卷积对照。历史、调用 / 紧凑 / 英文及任务明细的离屏截图与基线逐像素相同；设置仅版本号变化，活动和额度的时间 / 动画部分通过既有交互和实际窗口验证。

```powershell
$goExe = node -p "require('./scripts/go.cjs')"
& $goExe test ./...
& $goExe vet ./...
& $goExe test -race ./internal/monitor ./internal/nativeapp
& $goExe test ./internal/monitor -run '^$' -bench '^BenchmarkReview' -benchmem -benchtime=1s -count=3
& $goExe test ./internal/nativeapp -run '^$' -bench '^Benchmark(Widget|Review)' -benchmem -benchtime=1s -count=3
npm run test:pi
npm run native:check
npm run package
npm run package:check
```
