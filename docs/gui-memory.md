# 2.8.3 GUI 内存优化

基线为 2.8.2（`04f20703979b0e65837c4a5b5f6adaf4caff357b`）。本轮降低真实 GUI 进程的常驻和峰值占用，保留 GPU 加速、五页布局、透明效果、动画、后台采集及统计口径。

## Windows 进程测量

私有字节是进程的私有提交量，包含尚未驻留的页；私有工作集是当前驻留的私有页，更接近任务管理器的进程内存显示；工作集还包括共享页。上述数值来自 Windows 计数器，没有把累计 Go 分配量当作常驻占用，也没有调用 `EmptyWorkingSet` 将内存换出以制造下降。

[gui-memory-results.json](gui-memory-results.json) 保留每轮指标、范围、堆状态和显示准备时间。驱动驻留、GC 时机及 CPU 时间有波动，新版 CPU 时间为 2.250 / 2.297 / 2.734 秒；三轮本机样本不能证明跨设备的等比例收益或统计显著性。

## 改动

1. 背景的两个径向渐变直接生成一张不可变 RGBA 图，取消通用 SVG 的全窗口覆盖、图层和几何工作区。只缓存当前尺寸和主题；坐标、256 级查表、预乘及整数叠加舍入保持相同，浅色 / 深色、多种尺寸及 DPI 的逐像素对照通过。
2. 1254×1254 图标在普通 DPI 下先缩小，启动时按已有屏幕最大 DPI 准备完全相同的第一层，保留 627×627 及其后续层，去掉 6,290,064 字节的原始像素常驻引用。遇到更高 DPI 时重建；到奇数尺寸停止提前缩小，以保持任意小数 DPI 的图层选择。原 PNG 文件不变。
3. 收缩动画结束后释放卡片、四个指标层、卡片像素与模糊工作区。展开时按模型重建；形态动画结束后释放模糊工作区。隐藏两秒后释放全部离屏绘制器及 Win32 DIB，快速反向切换保留缓存，延迟回调检查代数和可见性。
4. GUI 默认 `GOGC=50`，Go 运行时软预算为 `max(80 MiB,32 MiB+16×窗口像素数)`，为高 DPI / 大窗口留出绘制空间。显式 `GOGC` / `GOMEMLIMIT` 优先；CLI、stdio、修复和更新检查不会设置此策略。隐藏缓存释放后，在 GUI 线程外执行一次合并回收，让没有后续分配的托盘状态也归还空闲页。

**80 MiB 是 Go 内存软预算，应用总进程内存可以超过它。** Direct3D、Win32、系统字体和驱动仍有固定占用，较大场景也会增加软预算。每帧 RGBA 导出复制仍存在。

## 成本与验证

释放缓存后再次显示圆球的准备时间为 **2.63 → 18.06ms**；首次卡片准备为 **120.27 → 118.43ms**。这些计时包含 GUI 线程上的绘制和显示请求，不含完整淡入时间。隐藏两秒后的展开卡片也通过实际 Win32 冷恢复验收。持续动画和快速切换保留原流程。

关闭 GPU 的试验使总 CPU 时间约增加至 4.7 倍，未采用；48 MiB Go 预算引发频繁 GC，也未采用。没有增加依赖、修改数据库结构或降低图像质量。

单独的背景初始离屏绘制基准为 **407.64 → 149.59ms（-63.3%）**，每次累计分配 **81.54 → 44.56 MiB（-45.3%）**。三次、每次一秒，1380×960 DIP / 150% DPI，包含测试绘制器构建及初始 100% 绘制；这不是窗口每帧耗时，也不是常驻内存。

安装包为 **7,838,608 → 7,882,088 字节（+0.55%）**，签名更新归档为 **9,514,308 → 9,580,521 字节（+0.70%）**。新增采样、诊断和恢复验收代码使本轮包体略增，运行文件仍只有主程序与图标。安装、升级、快捷方式、注册表、已安装服务、数据库修复、运行保护和卸载验收通过。

已通过完整 Go 测试、`go vet`、监测 / UI race 检查、Pi 测试及真实原生界面验收。新增回归验证背景逐像素相同、35 / 40 DIP 图标在 80%～1600% DPI 下与原图相同、缓存释放后重建像素相同、结束后的模糊释放、显式 GC 设置优先和大窗口预算。原生验收确认隐藏两秒后绘制器 / DIB 已释放、冷恢复成功；五页、调用、透明、拖动、键盘、过期 / 断连、置顶、窗口控制和快速反向切换继续通过。

## 复现

Windows amd64，AMD Ryzen 7 8845H，Go 1.27.1，MyGO 0.2.15，GOMAXPROCS=16。两版使用同一合成 20,000 条调用数据库、同名可执行文件及生产链接参数；离线，不启动 Codex App Server。主流程无截图和诊断强制 GC，新版正常运行的空闲回收保持启用。

基线检出 2.8.2，只复制 `memory_smoke.go` 并增加 `--smoke-memory` 入口，不复制产品优化或内存策略。公共辅助代码驱动总览、五页、全部调用、卡片、圆球、托盘、恢复及再次显示圆球。阶段名 `cold-card` 是早期辅助代码标记，实际再显示的是收缩圆球；JSON 已注明。

```powershell
$goExe = node -p "require('./scripts/go.cjs')"
pwsh -NoProfile -File scripts/gui-memory.ps1 -Baseline '<2.8.2 exe with common helper>' -Candidate 'build/native/Codex Monitor Native.exe' -Fixture 'artifacts/performance-2.8.2/profile' -Repetitions 3 -Output 'artifacts/gui-memory/final-memory.json'
node scripts/gui-memory-summary.cjs
```

脚本用 `PROCESS_MEMORY_COUNTERS_EX2` 采样私有工作集，确认调用总数 20,000、当前页 50 条。更换数据集时用 `-ExpectedCalls` 指定记录数。全部逐时样本由 Git 忽略，随 Release 提供 `gui-memory-samples.json`，汇总 JSON 保留每轮指标与堆状态。

单独诊断可设置 `MONITOR_MEMORY_PROFILE=1`，运行 `--smoke-memory --capture-dir <目录>` 生成各状态的 pprof 堆快照。诊断会主动 GC，不用于上述进程指标。上一轮的统计 / 包体积收益见 [2.8.2 报告](performance.md)。
